# 最终系统验收报告

验收对象是 UrbanNoiseLab 终稿复核。日期是 2026-11-10。对照的基线是 `main` 上的 `ad9a25451d9ef8297cd8e7d1dd0f50b515f42e49`。本报告只记录这一轮实际执行过的检查。

状态用四种：Passed、Partially Passed、Failed、Not Verified。

## 完成的功能

系统仍是原来的 React 与 FastAPI 实现。管理员、发布者、采集者，任务状态机，合成世界，YJMob100K 与 GeoLife 轨迹，NoiseCapture 小时箱，以及 random、nearest、greedy、uncertainty、min_cost、MU-PSA、EER-Reach、LinUCB 都还在。

这一轮没有新的模型，没有重跑 210 个公平回合、80 个真实轨迹回合和 135 个鲁棒性回合，也没有重下 227 个 NoiseCapture 国家包。

## 修复的问题

LinUCB 不再把到达概率为 0 的配对放进候选。人必须在线，成本不能超过剩余预算，同一人和同一格子不能重复。单元测试是 `test_linucb_skips_unreachable_pairs`。公平主表没有改写。修订后的 bandit 写在 `experiments/results/phase2/bandit_reach_gate/results.json`。

GeoLife 加载会丢掉纬度超出 −90 到 90、经度超出 −180 到 180 的点，网格原点只用剩下的点。预处理里已有的超速和重复时间戳规则没有改。全量清洗统计仍是接受 24,173,770、拒绝 703,208。

真实数据缺失或 Fully-Real 不成立时返回 409，错误码 `scenario_data`，正文以“数据未切换”开头。删除数据表发生在加载成功之后，所以上一场世界不会被合成轨迹替换。

仿真页的下拉框在进入页面时与服务器上的世界对齐，用户改过参数之后不会被一次迟到的刷新盖掉。重置和步进在请求结束前不能连点。顶栏时钟在切换页面时刷新，并大约每 2 秒更新。

Windows 启动脚本改为从仓库根目录工作，默认数据目录是仓库下的 `data`，并用 `npm.cmd` 启动前端。这些修改没有在 Windows 上运行。

检查发生在 Linux 云端代理，不是 Windows 11。Python 来自仓库 `.venv`，版本是 3.12。前端是 Vite 8.3.7。浏览器是本机 Chrome，视口 1440×900。API 监听 `127.0.0.1:8000`，网页开发服务器监听 `127.0.0.1:5194`，代理到 8000。演示数据库是临时 SQLite，不进入 Git。YJMob 使用本机已有的 `data/processed/yjmob/dataset1.parquet`，只取 10 个用户。

## 算法实验结论

EER-Reach 在合成 regular、预算 8 的主表上平均 MAE 最低，是 10.081±1.965。complex 的预算 4 和 12 上，reach_random 的平均更低。真实移动窗口上，EER-Reach 没有普遍最低。法国与卢森堡噪声留出的 R² 仍是 −0.352 和 −0.432。

这些负结果保留。局部方差下降不等于全局误差下降。完成率高也不等于 MAE 低。

LinUCB 的输出变了，所以单独重跑了与主表相同训练设置的 bandit。regular 预算 8：MAE 11.087±2.102，成功 3.33 次，平均到达概率 0.467。complex 三个预算都是 MAE 10.203±1.351，成功 2.00 次。它不再分配到达概率为 0 的人，也仍然不是最好的方法。`fair_main/summary.json`、`real_runs.json` 和 `robust_fair/results.json` 没有被覆盖。主表和旧图里的 bandit 必须称为修订前。

## 已知局限

原始轨迹和噪声包不在 GitHub 上，工作区结束后可能消失。恢复命令在 README。演示用的是 10 人子集加合成噪声，不是全量，也不是 Fully-Real。EER-Reach 没有空间协方差。LinUCB 不是 PPO，训练只有两个回合。Windows 是否能在答辩电脑上一次启动，还要用户自己执行检查表里的命令。
