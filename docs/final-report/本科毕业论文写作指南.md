# 本科毕业论文写作指南

这份指南说明怎样把 `UrbanNoiseLab_完整系统报告.md` 收成一篇软件工程本科论文。系统报告已经有设计、公式、实验和截图，论文不需要把它再扩写一倍，也不要把工程改进写成理论突破。

## 1. 推荐论文题目

人机混合城市噪音预测采样与智能任务分配系统的设计与实现

若学院要求题目里出现“研究”，可以用：

面向移动参与者的城市噪声预测采样与动态任务分配方法

副标题可以写 UrbanNoiseLab。不要使用“最优”“全局误差最小化”或“深度强化学习”作为题目。

## 2. 推荐章节结构

1. 绪论。问题、群智感知和稀疏采样的背景、本文要做的事、论文结构。
2. 相关工作。移动群智感知、稀疏噪声采样、任务分配。阅读深度按 `docs/research/references.bib` 和 `docs/research/literature_review.md` 写，没有读到全文的文献不要写成细读。
3. 需求分析。三种角色、任务状态、数据模式、不能做 Fully-Real 的原因。
4. 系统概要设计。架构、模块、数据库、部署。部署只写 Windows 与 Linux 虚拟环境，不写 Docker。
5. 详细设计与实现。状态机、地图、仿真时钟、接口。
6. 动态任务分配方法。到达概率、局部方差下降、成本、重规划、LinUCB 的位置。
7. 实验与结果。协议、合成对照、真实轨迹、真实噪声留出、负结果。
8. 系统测试与演示。测试范围、一次完整操作、已知未在 Windows 上执行的部分。
9. 总结与展望。三方面贡献和局限。

学校若规定“绪论、相关技术、需求分析、概要设计、详细设计、实现、测试、总结”，就把第 6 章并进详细设计，把第 7 章并进测试。不要为了凑章再造一个深度学习章节。

## 4. 研究问题和主要贡献

研究问题可以写成三句：

1. 在参与者持续移动、采样预算有限时，如何选择下一时间片的采集任务。
2. 只按当前距离分配会怎样失败，到达概率和噪声不确定度能否一起使用。
3. 在合成场、真实移动轨迹和真实噪声观测上，任务完成率和地图误差分别说明什么。

贡献建议只写三条，并和系统报告一致。

贡献一：完整的人机混合城市噪音采样系统。实现了用户、采样任务、采集执行、动态分配和环境预测。三种角色和任务状态机可以在界面上走通。

贡献二：面向动态移动参与者的预测采样算法。分配使用移动可达性、噪声预测的局部信息价值和采样预算。EER-Reach 是带到达约束的一步方差下降，LinUCB 只在到达概率大于 0 的配对上选择。二者都不是新的理论最优算法。

贡献三：真实数据与模拟数据结合的实验验证。真实人类轨迹驱动参与者位置，真实噪声观测单独做留出预测，合成场用来做可控对照。做不到时间和地点都真实的联合实验时，系统拒绝并保持原世界。

## 6. 适合放进论文的关键公式

公式和代码的对应关系以系统报告第 6 章为准。论文里建议保留下面几条，并在公式后写函数名。

到达分布。下一片位置来自 0.55 的时段频率和 0.45 的转移概率，实现在 `MobilityFit.distribution`。论文要说这是经验频率，不是神经网络预测。

预测。反距离加权在能量域做，k=8，幂为 2，时间权重 0.55，用地惩罚 3.5，标准差裁剪到 0.35–15。实现是 `predict_idw`。分贝不能先算术平均再参与插值。

局部方差下降。设预测方差 v、测量噪声方差 r，下降量是 v²/(v+r)。实现是 `expected_error_reduction`。论文里写明：只更新被选中的格子，没有空间协方差，因此不等于全局期望绝对误差的下降。

EER-Reach 分数。到达概率不低于 0.22 时，用到达概率、接受概率、质量和上述下降量，减去 0.35 倍成本。否则不选。实现在 `assignment.py`。

成功条件。存储的未来格子等于任务格子，并且接受抽样通过。预算在分配时扣减，失败退回，成功才计入花费。

LinUCB。上下文是到达、距离、价值、不确定度、重复、预算比例和时间比例。探索只发生在到达概率大于 0、人在线、成本不超过剩余预算的配对上。不要把更新公式写成 PPO 的策略梯度。

## 7. 实验结论的正确表述

可以写：

在 8×8 合成 regular 场景、3 个种子、预算 8 的公平协议下，EER-Reach 的平均 MAE 为 10.081±1.965 dB，低于同表中的 nearest、mupsa 和修订前的 bandit。预算从 8 增到 12 没有继续降低这个平均值。

在 complex 场景，预算 4 与预算 12 的最低平均来自 reach_random，预算 8 的最低平均来自 EER-Reach。因此不能写“所提方法在全部合成场景优于全部基线”。

在 YJMob 与 GeoLife 的真实轨迹窗口上，合成噪声场中的最低平均 MAE 分别来自 min_cost、random 或 nearest。EER-Reach 没有在这些窗口上普遍最低。这说明到达概率高的采样，不一定降低全图误差。

法国 NoiseCapture 小时箱留出：MAE 18.260，RMSE 22.413，R² −0.352。卢森堡：MAE 15.524，RMSE 20.770，R² −0.432。应写成当前插值不足以预测这种稀疏手机观测。

LinUCB 修订前的主表行保留。修订后的数字只引用 `bandit_reach_gate/results.json`，并说明其他方法没有重跑。

样本是 2 或 3 个种子。标准差经常大于 1 dB。论文使用“这组样本上的平均”，不使用“显著优于”。

## 8. 答辩前要核对的参考文献

打开 `docs/research/references.bib`，逐条核对将要放进论文的 DOI、作者、年份和题名。bib 头部写明这些条目在 2026-11-09 对过 Crossref 或 OpenAlex。学校格式可能要求 GB/T 7714，需要从 bib 再排一次，不要只贴 BibTeX。

优先核对这几条，因为正文会引用：

- Yabe 等，YJMob100K，Scientific Data，2024，DOI `10.1038/s41597-024-03237-9`
- Picaut 等，NoiseCapture，Building and Environment，2019，DOI `10.1016/j.buildenv.2018.10.049`
- Wang 等，Sparse mobile crowdsensing，IEEE Communications Magazine，2016，DOI `10.1109/MCOM.2016.7509395`
- Song 等，Limits of Predictability in Human Mobility，DOI 以 bib 中 `song2010limits` 为准

`docs/research/literature_review.md` 里标成摘要级的文献，论文里就写“据摘要”，不要写成“本文复现了该文实验”。`docs/research/negative_results.md` 记录了若干 PDF 没有读到全文。那些文献可以出现在相关工作的概述里，不能出现在“与原文公式逐步对比”的段落里。

## 9. 当前方法的局限

- 到达模型是时段频率和一阶转移，不预测长距离意图。
- 噪声预测是局部反距离加权。真实手机数据上 R² 为负，说明这个不确定度不能当成可靠的全局误差估计。
- EER-Reach 忽略空间相关，局部价值高不等于全图误差下降。
- LinUCB 只有两个训练回合，上下文维度固定，不能称为学会了分配策略。
- 公平主实验是 8×8、少量人和机器、2 到 3 个种子。
- 真实轨迹实验的噪声场仍是合成的。真实噪声实验没有同时使用这些轨迹。
- 演示加载 10 个 YJMob 用户，不是全量 10 万。
- 原始数据不在 Git 中。换一台机器必须先恢复 `data/processed`。
- Windows 脚本没有在 Windows 11 上执行过。

## 10. 不应夸大的表述

下面这些句子不要出现在摘要、贡献或答辩结尾：

- 提出了全局最优的城市噪声采样算法。
- EER-Reach 实现了空间高斯过程的期望误差下降，并具有 (1−1/e) 保证。
- 使用 PPO 或多智能体强化学习完成任务分配。
- 所提方法在所有预算、所有场景和真实数据上都取得最低误差。
- 真实轨迹与真实噪声已经构成 Fully-Real 联合实验。
- YJMob100K 的网格是北京市或东京市的实测街区。
- 10 个用户的窗口等于 10 万用户的轨迹预测。
- 夹具或 Synthetic Demo 的截图是全量数据实验。
- 系统通过 Docker 部署。Docker 不是本项目的运行方式。
- Linux 上的测试通过，等于 Windows 11 已经测试通过。

摘要的最后一句建议写成：系统可以完成从任务发布、可达性约束分配到采样回写的演示；在部分合成场景中，带到达约束的局部方差下降优于只看距离的分配；该优势不能推广到全部场景和真实噪声预测。
