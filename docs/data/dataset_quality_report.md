# 数据集质量报告

计数来自 `scripts/preprocess_datasets.py` 写出的 JSON，以及本脚本对 Parquet 的复核。没有采用论文或网页上的人数来替换这些计数。

## YJMob100K

- dataset1：111535175 行，100000 个 user_id，day 0–74（75 天），timeslot 0–47，x 1–200，y 1–200。
- dataset2：29389749 行，25000 个 user_id，day 0–74（75 天），网格范围与 dataset1 相同。
- 列只有 user_id, day, timeslot, x, y。`latitude_assigned` 为 false。坐标系统是 `yjmob_virtual_500m`。没有把网格标成北京、东京或其他真实城市。
- dataset2 的去重人数是预处理脚本数出来的 25000。本报告不把它改成记录页面上的描述性文字。

## GeoLife

- plt 文件 18670，用户目录 182，原始点 24876978，30 分钟均值箱 84742。
- 原始扫描的时间范围 2000-01-01T23:12:19 到 2012-07-27T08:31:20。原始包围盒 {'lat_min': 1.044024, 'lat_max': 400.166666666667, 'lon_min': -179.9695933, 'lon_max': 179.9969416}。纬度最大值 400.166666666667 不是合法 WGS84 纬度，说明至少有一个原始点没有通过坐标合法性检查就被扫进了包围盒。
- 全局最忙的两个日历日是 {'day0': '2009-02-14', 'day1': '2009-02-15'}，对应 episode 行数 544，用户 32。这是预处理时按箱数选出的两天，不是算法运行时改写的轨迹。
- 对 `slots_all.parquet` 的复核：{'bins': 84742, 'valid_bins': 84742, 'lat_min': 1.234408995575221, 'lat_max': 64.751993, 'lon_min': -176.20028566666667, 'lon_max': 175.61915, 'users': 182}。箱内均值都落在合法经纬度范围内；一个坏点和同槽的正常点求平均后，坏点不会单独留在箱里。
- 距离使用赤道半径 6371000 m 的等距圆柱投影。仿真重新按所选子集的最小经纬度编号，避免用这个全球包围盒当原点。
