# 演示环境检查表

在答辩机器上逐项看。做不到的项不要用口头解释掩盖。

## 软件

- Python 3.11 或更新版本。Windows 上 `py -3` 或 `python` 至少有一个。
- Node.js 带 npm。Windows 启动脚本使用 `npm.cmd`。
- 已执行 `scripts/setup_windows.ps1` 或 `scripts/setup_linux.sh`。存在 `.venv` 和 `apps/web/node_modules`。
- 不安装、不启动 Docker。

## 端口和进程

- API：http://127.0.0.1:8000/api/health 返回 `{"status":"ok"}`。
- 网页：http://127.0.0.1:5173 打开登录页。
- 若端口被占用，设置 `UNLAB_API_PORT` 和 `UNLAB_WEB_PORT` 后再启动。Vite 使用 `--strictPort`，端口被占会直接失败，而不是悄悄换端口。
- 数据目录：默认是仓库下的 `data`。换盘符时设置 `UNLAB_DATA_DIR`。路径不要带未加引号的空格。

## 这一场要用的数据

- `data/processed/yjmob/dataset1.parquet` 存在。演示只读 10 个用户的窗口，但文件本身是预处理结果。
- 不要求 `hourly_500m.parquet` 的全部国家。噪声页如果要讲法国留出，再确认 NoiseCapture 小时箱在本机。没有它，就只讲合成噪声场上的 YJMob 轨迹，并说明留出数字来自已经写入的 JSON。
- 打开仿真，Fully-Real 必须失败并出现“数据未切换”。这一项用来确认系统没有把缺失数据换成合成轨迹。
- Real-Mobility + YJMob dataset1 重置后，用户数是 10，移动来源是 YJMob100K，噪声来源是 synthetic_field，预算剩余等于预算总额，已花费是 0。

## 建议的一场参数

- 数据模式：Real-Mobility
- 移动来源：YJMob dataset1
- 场景：complex
- 种子：7
- 算法：eer_reach
- 预算：24
- 真实用户上限：10
- 手工任务：标题“答辩采样点”，时间片 50–54
- 然后执行分配，再前进 4 步

参考结果：分配后剩余 19.60；四步之后剩余 20.60，已花费 3.40；一条失败退款，两条成功测量。若种子或预算被改过，以页面为准。

## 失败时怎么停

- 重置后红字是“数据未切换”：不要继续把旧世界讲成新数据。改回已经成功过的 YJMob 再重置一次。
- 重置按钮按下去没有日志：等请求结束。按钮在请求期间是禁用的，不要连点。
- 页面下拉框和状态行不一致：看状态行。状态行是服务器上的世界。下拉框只是下一次重置要提交的参数。
- 分配结果是 0 条：预算可能已经用完，或时钟已经到评估期末尾。按上表重新重置。
- 实验页没有曲线：结果文件不在 `experiments/results/phase2/fair_main/summary.json`。不要当场重跑 210 个回合。可以讲报告第 9 章的表。
- 顶栏时钟比仿真页慢一两秒：顶栏大约每 2 秒刷新。等它走到 D1 02:00 再讲。

## Windows 现场命令

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\setup_windows.ps1
$env:UNLAB_DATA_DIR = "$pwd\data"
powershell -ExecutionPolicy Bypass -File .\scripts\start_windows.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\test_windows.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\stop_windows.ps1
```

这些命令在写出本文件的 Linux 环境里没有执行。启动失败时看 `logs\api.err.log` 和 `logs\web.err.log`。

## 结束

讲完执行 `stop_windows.ps1` 或 `stop_linux.sh`。不要把演示数据库、原始 parquet 或密钥提交到仓库。
